## Differences from VAREL
1. List: one keyset SQL query, no totals or offset pages (`pageCount` "25+" style); sort whitelist as VAREL.
2. Money is cents in the database; `weight`/package dims are decimals → numbers on the wire.
3. Images: https URLs or platform public files (`/__platform/files/<fileId>/…`) uploaded through
   `/manage/uploads` (3-step platform flow; bytes never reach the Worker, so no magic-byte sniff:
   type/size checked on the grant and the stored type re-checked on complete). Platform links in a
   product must belong to a ready `media_uploads` row (422 `images.<i>.src` "Upload this image again").
4. New server rules mirroring the editor: compare-at must be above the price; a digital product needs
   its download file; an ordered product's type cannot change.
5. `orderCount` is bounded (101 means "100+"); deleting an ordered product archives it (as VAREL) and answers `{archived: true}`.
6. Variant upsert in PATCH is done inside one transaction (removed SKUs deleted, cart lines cascade).
7. Bulk actions: no bulk endpoint (as VAREL): the client runs per-product requests, ≤ 6 at a time.
8. Icons: VAREL's Send / FilePen / Archive are not in the kit; closest kit icons used.
