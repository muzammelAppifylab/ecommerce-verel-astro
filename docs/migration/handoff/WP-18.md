## Differences from VAREL

- Inventory list is filtered in SQL and keyset-paged (product position, product id, variant position,
  SKU), "Load more" instead of numbered pages; the header says "50+ variants". `sort` is not accepted
  (the UI never sent it); `?page=` is dropped from the screen search.
- Adjust is one atomic `UPDATE … GREATEST(0, inventory + n)`; bulk is one `UPDATE … FROM unnest()`,
  all-or-nothing with per-item field errors (`updates.<i>.variantId`), repeated SKUs: last wins.
  Both touch `products.updated_at`.
- Taxonomy: ids Int in the DB, strings on the wire; product counts capped at 101 (UI shows "100+");
  at most 100 departments / 100 categories per department (409 `limit_reached`); single-row answers.
  Delete refusals answer 409 `in_use`; slug clashes 409 `slug_taken` with `fields.name`.
- Departments are editable by anyone with `manageProducts` (staff by default); VAREL allowed only
  admins in the UI. Read-only view for other staff.
- Add / rename are a `Modal` with a labelled field (AGENTS form rules) instead of inline inputs.
- CSV export adds the formula guard (`'` before `= + - @`) and CRLF line ends.
- Variant SKU input strips whitespace; duplicate effective SKUs show "Duplicate SKU" on the row live.
  `currencySymbol` prop (default `$`) added to VariantsSection.
- Swatches are SVG (CSP); icons `equal`, `diff`, `circle-slash` are not in the kit, so the bulk bar
  uses `pencil`, `chevrons-up-down`, `ban`.
- Translation queueing calls F3's `queueEntityTranslation(db, 'department'|'category', id, {requestUrl})`
  after create/rename (a no-op until WP-25).
