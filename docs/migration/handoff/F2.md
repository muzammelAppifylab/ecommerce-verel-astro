# F2 · Storefront design system and shell: hand-off

Branch `wp/F2` (F1 merged in). Owns `src/styles/storefront.css`, `public/fonts/**`, `public/images/**`,
`public/favicon.svg`, `src/components/{varel,ui,layout}/**`, `src/layouts/{Storefront,AuthShell,CheckoutShell,Base}.astro`,
`src/lib/stores/**`, `src/lib/utils.ts`, `src/pages/styleguide.astro`. Also wrote the WP-09 slot
`src/components/cart/BagDrawerContent.tsx` (stub body, WP-09 replaces it) and `tests/storefront-shell.test.ts`.

## What was ported

- **Styles** `src/styles/storefront.css`: Tailwind v4 (`@import "tailwindcss" source(none)` + `@source` on the
  storefront folders only), VAREL `src/index.css` + `src/styles/tokens.css` as `@theme` tokens (ink scale, surfaces,
  type scale `display-1…5`, `body-*`, `label-*`, tracking, easing/durations, `max-w-page`…), shadcn variants,
  page-transition CSS for the ClientRouter, nav-progress bar, and class replacements for every VAREL inline style
  (`.ghost-wordmark`, `.wordmark`, rich-text colour classes). Tailwind is never imported by the dashboard.
- **Fonts**: self-hosted woff2 (Cormorant Garamond normal + italic variable, Lato 300/400/700; latin + latin-ext),
  `font-display: swap`, OFL licences in `public/fonts/`. The display face is preloaded by the three shells.
- **`src/components/varel/**`**: every VAREL varel component as React (Badge … Wordmark, ProductTile/Grid/GridItem,
  NewsletterForm via `siteFetch('/site-api/newsletter')`, RichText, Toast + `Toaster`), CSP-safe: no `style={}` in SSR
  output (`useElementStyle` applies computed values through the CSSOM after hydration). Words: `TextProvider` /
  `useText(ns)` (islands get their dictionaries as props), English fallback `text-en.ts`. Links: `href.ts`
  (`localizeHref`, `stripLocale`, `isActivePath`; VAREL `/login` `/signup` `/admin` → D13). `Wordmark.astro` for
  server-only chrome. `Styleguide.tsx` (the /styleguide/ catalogue).
- **`src/components/ui/**`**: the shadcn/Radix primitives the storefront uses (breadcrumb, button, checkbox, dialog,
  dropdown-menu, input, label, radio-group, select, sheet, skeleton, switch, tabs, textarea, tooltip, remove-scroll).
- **`src/components/layout/**`**: `chrome.ts` (server: reads `GET /site-api/settings/public` + `GET /site-api/menus`
  in-process, builds plain props; VAREL fallback copy/menus when they fail), `menus.ts` (CMS menus + fallbacks,
  label translation), `dictionaries.ts` (server catalogs from `src/locales/<loc>/<ns>.json`, per-island picks),
  `SiteHeader.tsx` (header + `MobileMenu` + `BagDrawer` frame, one `client:load` island), `LanguageSwitcher`,
  `LanguageFlag`, `CookieBanner` (+ consent store), `FooterIslands` (newsletter, language), `AnnouncementBar.astro`,
  `Footer.astro` (server-rendered, two `client:visible` islands, "Cookie settings" via `[data-consent-open]`),
  `NavigationProgress.astro` (ClientRouter events), `auth-images.ts`.
- **Stores** `src/lib/stores/`: `bag.ts` (count, wishlist ids, drawer open; `CustomEvent` + `sessionStorage`,
  `bag.sync()`, `bag.add()`, `bag.applyCart()`), `ui.ts` (menu/search/bag), `consent.ts`, `toast.ts`. No library.
- **Layouts**: `Storefront.astro` (skip link, progress, announcement, header, `<main id="main">`, footer, cookie
  banner, toaster; `data-store-currency` for `money()` in islands), `AuthShell.astro` (split image layout, props
  `image`, `imageAlt`, `imageSide`, `maxWidth` 440|460, `footer` slot), `CheckoutShell.astro` (back to bag ·
  wordmark · secure checkout, no footer). All three wrap `<Base chrome="none">`.
- **`Base.astro`**: new props `chrome: 'site' | 'none'` (default `site` = template header/footer/global.css, so every
  template page is unchanged), `locale` (default `Astro.locals.locale`, then `SITE.lang`) → `<html lang>`,
  `alternates` → `hreflang` links + `x-default`; canonical keeps the locale prefix; `<slot name="head" />`.
  `global.css` is now linked through `?url` only when `chrome="site"` (its unlayered rules would beat Tailwind's
  layers on storefront pages). All SEO behaviour (title, description, OG/Twitter, JSON-LD, ClientRouter, session
  refresh, static hydration) unchanged.
- **`/styleguide/`**: every component, variant and state (dev server and Preview only; 404 on live).

Checked: `tsc --noEmit` clean; `npm test` 27 files / 200 tests pass (with `TEST_DATABASE_URL`); `npm run build` ok;
/styleguide/ renders at 1440 and 375 (no horizontal scroll), mobile menu and bag drawer open, template pages
(`/about/`) still styled by global.css. The only console errors are 404s for `/site-api/cart` and
`/site-api/wishlist` (routes come with F3/WP-09/WP-10).

## Usage

```astro
---
const {api, site, viewer} = await pageContext(Astro.request, Astro.response);
---
<Storefront site={site} viewer={viewer} api={api} title="Shop" description="…">…</Storefront>
```
Prerendered page: `staticContext()` + `isStatic`, no `api`. Islands: wrap in `<TextProvider locale dicts>`; get
dictionaries on the server with `dictsFor(locale, {product: true, common: ['close']})`
(`src/components/layout/dictionaries.ts`, server only). Add to bag from any island: `bag.add({...})`; the header
count and drawer follow.

## Differences from VAREL

- Header, mobile menu and bag drawer are one island; footer, announcement bar and shells are server HTML.
- Navigation progress follows `astro:before-preparation` / `astro:after-swap` instead of TanStack Router state.
- Tooltip brings its own `TooltipProvider` (no app root to mount one).
- `PageLoader` / `RouteError` not ported: pages are server-rendered; 404/500 belong to WP-07.
- Footer "Sign in" → "Account" swap is server-side, or `data-guest-only`/`data-user-only` on prerendered pages.
- Favicon replaced with VAREL's.

## Requests

1. **F3**: `vitest.config.ts` has no `@/` alias, so tests cannot import modules that use `@/…` (most storefront
   code). Please add `{find: /^@\//, replacement: fileURLToPath(new URL('./src/', import.meta.url))}`.
2. **F3 / WP-01**: the chrome expects `GET /site-api/settings/public` (VAREL `PublicSettings`: `announcement`,
   `currency`, `supportEmail`, `phone`, `legalName`, `vatNumber`, `businessAddress`, `socialLinks`, `cookieConsent`,
   `locales`, `defaultLocale`) and `GET /site-api/menus` (`[{key, title, items: [{label, url}]}]`), both honouring the
   `x-locale` header.
3. **F4**: `Astro.locals.locale` (typed in `env.d.ts`) and `src/locales/<loc>/<ns>.json`; the shell reads them through
   `import.meta.glob('/src/locales/*/*.json')` and falls back to English. `localizeHref`/`stripLocale` live in
   `src/components/varel/href.ts`; `src/lib/links.ts` may re-export them.
4. **F3**: `astro.config.mjs` `redirects: {'/account': '/account/login/'}` conflicts with D6 (`/account/` is the
   customer app); remove it when WP-13 lands.
5. **WP-07 / WP-15 / WP-12**: move pages onto `Storefront` / `AuthShell` / `CheckoutShell`; template pages keep the
   old chrome until then.
6. **WP-25 / I1**: pass `alternates` for pages outside the storefront layout if they need hreflang.

## Known gaps

- `setMoneyContext` is module state; on the server the store currency/locale is set per page render by
  `Storefront.astro` (concurrent renders in different languages could interleave formatting).
- `/site-api/cart` and `/site-api/wishlist` answer 404 until their packages land; the header shows 0 until then.
- `astro check` is not available; `.astro` files were checked by build and by rendering only.
