## How the account screens plug into WP-13

`host.tsx` finds WP-13's modules by file (`import.meta.glob` of `src/account/i18n.tsx` → `useAccountT`,
`useAccountContext`; `src/account/useTitle.ts` → `useTitle`), so neither package edits the other. WP-13's names on
its branch match. Without them (tests) `OrdersTextProvider` supplies the dictionary.

WP-13's router must register (basepath `/account`):

```ts
/orders/          lazyRouteComponent(() => import('./screens/orders/OrderHistory'))   validateSearch: s => ({status: orderStatusOf(s)})
/orders/$number/  lazyRouteComponent(() => import('./screens/orders/OrderDetails'))
```

and pass `ACCOUNT_NAMESPACES` incl. `orders`, `returns`, `checkout`, `account` (it already does). The cancel
mutation invalidates `['orders']` and `['account', 'overview']`.

## Differences from VAREL

1. **Security:** a return lookup by the order number alone returns a REDACTED order (masked email, no phone,
   address, card, tracking, download links; `access: 'number'`), and booking a return needs the signed-in owner or
   the order's email (422 `fields.email`). VAREL returned full PII to anyone holding an order number.
2. A guest order counts as the signed-in customer's only when their email is **verified** and matches exactly.
3. Order history is a keyset page (`CursorPage<Order>`, 20 per page, ≤ 50) with "Show more orders"; the count line
   is "N orders" / "N+ orders" (no `count()`). VAREL returned the whole history as `Order[]`.
4. An aged access token answers `401 token_expired` (siteFetch refreshes and retries) instead of "not found" or a
   redacted view.
5. Duplicate `lineId`s in one return request are summed (VAREL bug); at most 50 return requests per order (429);
   `lineId` stored as a number.
6. Amounts on these screens are in the order's currency (VAREL used the store currency for some line amounts and the
   estimated refund).
7. Returns page URL sync uses `history.replaceState` only (Astro's ClientRouter owns popstate), so back/forward do
   not replay lookups. The fulfilment label in the return header is localized (VAREL showed raw English).
8. Invoice tab title uses the store name (`invoice.documentTitle`), not a hard-coded "VAREL".
9. Kept VAREL gaps: the cancel toast promises a confirmation email even for unpaid orders (only `order_refunded` is
   sent, and only when money went back); booking a return sends no email (no `return_requested` template exists).
