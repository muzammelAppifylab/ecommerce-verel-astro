# F1 · Schema, migrations, seed: hand-off

Branch `wp/F1`. Owns `prisma/schema.prisma`, `prisma/migrations/2026110*`, `prisma/seed.sql`,
`scripts/gen-seed.ts`, `tests/integration/support/harness.ts` (TRUNCATE list).

## What was ported

- **Schema** (`prisma/schema.prisma`, section "VAREL shop"): every VAREL model except `User`, `Session`,
  `PasswordResetToken`, `StaffInvite` (D5), plus `CustomerProfile` and `Visitor`. 36 new tables.
- **Migration `20261101090000_varel_schema`**: `CREATE EXTENSION pg_trgm`, the tables, FKs and indexes
  (generated by `prisma migrate diff`, so the schema and the database match: a later
  `migrate diff` is empty), CHECK constraints for every fixed set and money column, the partial index
  `carts_abandoned_idx`, and the `settings` singleton row (`id = 1`, schema defaults).
- **Migration `20261101090100_varel_roles`**: role `staff` (system role, editable), the seven §7
  codenames, and their default grants (admin: all seven; staff: all but `site:store_settings:manage`).
  Idempotent, matched by slug/codename.
- **Seed** (`prisma/seed.sql`, 1.3 MB, generated): VAREL's full demo data converted to this schema.
  `scripts/gen-seed.ts` reads a database that VAREL's own seed filled (its header has the commands)
  and writes the SQL, so the engine-priced orders, rendered demo emails and hashed translations
  are VAREL's exact output.
- **Test harness**: every new table in the TRUNCATE; the settings row is re-created after it.

Checked: on an empty database, `prisma migrate deploy` + `prisma db execute --file prisma/seed.sql`,
**twice** (idempotent), then `migrate diff` (empty). `prisma generate` ok. `npm test` with
`TEST_DATABASE_URL`: 26 files, 190 tests pass. All 185 checked translation `source_hash`es (menus,
products, departments, post/page bodies, discounts, collections) match their seeded source, so
none show as stale.

## Mapping and conventions (what Wave 1 code must know)

| VAREL | Here |
|---|---|
| `Order`, `OrderItem`, `OrderEvent`, `Payment` | `ShopOrder` / `shop_orders`, `ShopOrderItem`, `ShopOrderEvent`, `ShopPayment` (D4). Prisma: `db.shopOrder`, `db.shopOrderItem`, `db.shopOrderEvent`, `db.shopPayment`. Relation names on the order are unchanged (`items`, `events`, `returns`, `redemptions`, `discountCodes`, `payments`, `discountRef`). |
| `Session` (`sessionId` on Cart/WishlistItem) | `Visitor` (`visitorId`, VarChar(64), the `visitor_id` cookie) |
| `User` (role, profile) | template `users` (`userId Int`) + `CustomerProfile` (`firstName`, `lastName`, `phone`, `locale`, `marketingOptIn` = VAREL `newsletter`) |
| Decimal money `price`, `compareAt`, `costPerItem`, `subtotal`, `discount`, `shipping`, `tax`, `total`, `amount`, `refunded`, `rate`, `freeShippingThreshold`, `minimum`, `maxAmount`, `value` (analytics) | `…Cents Int`: `priceCents`, `compareAtCents`, `costCents`, `subtotalCents`, `discountCents`, `shippingCents`, `taxCents`, `totalCents`, `amountCents`, `refundedCents`, `rateCents`, `freeShippingThresholdCents`, `minimumCents`, `maxAmountCents`, `valueCents` |
| `Discount.value` | split by kind: `percent` → `percentOff Decimal(5,2)`; `fixed` → `amountCents`; `shipping`/`bxgy` → neither (null) |
| Rates (`taxRate`, `TaxRate.rate`), weights, sizes, `ratingAvg` | still `Decimal` (fractions / measures, not money) |
| cuid ids | `Int` autoincrement: Department, Category, Post, Address, Cart, CartLine, WishlistItem, Discount, DiscountCode, DiscountRedemption, ShopOrder (+ items, events, payments), ReturnRequest, NewsletterSubscriber, ContactMessage, TaxRate, Collection, Page, Menu, EmailMessage, Review, Translation; `BigInt` for ActivityLog and AnalyticsEvent (serialize as string) |
| string ids kept | Product (`id` = slug), Variant (`id` = SKU), ShippingZone / ShippingMethod (slug ids carried by checkout), EmailTemplate (`key`), Setting (`id = 1`) |
| `Discount.categoryIds` / `departmentIds` / `customerIds` `String[]` | `Int[]` (`productIds` stays `String[]`) |
| `ReturnRequest.items[].lineId` (cuid) | `shop_order_items.id` (number) |
| `Translation.entityId` | the record's id as text (`"3"`; the slug for products); `option` / `post_category` keep the English value; setting `"1"` |
| `ContactMessage.order` | same field name, column `order_number` |
| Prisma enums | `VarChar` + CHECK, **same values and spelling** (`Paid`, `Unfulfilled`, `published`, `percent`…) |

Every table has `createdAt`/`updatedAt` (`Timestamptz(3)`), except append-only ones
(`wishlist_items`, `discount_redemptions`, `shop_order_events` (`at`), `shop_order_items`,
`analytics_events`, `activity_logs`). `ShopOrder` keeps `placedAt` and adds `createdAt`/`updatedAt`.

FKs to `users`: `Cascade` for `customer_profiles`, `addresses`, `carts`, `wishlist_items`;
`SetNull` for `shop_orders`, `discount_redemptions`, `reviews`, `activity_logs`. `analytics_events`
has no FKs (append-heavy). The `User` model only gained Prisma back-relation fields (no column).

Search: GIN trigram indexes on `products.name`, `products.brand`, `products.short`, `posts.title`,
`posts.excerpt` (`contains`/`ILIKE '%q%'` can use them).

### Seed conversions

- No users. VAREL's demo customer (Mira) is a guest: her orders keep their numbers with
  `mira.halvorsen@example.com`; her addresses, bag and wishlist are not seeded (they need an
  account). Every customer email is `@example.com`; store addresses (`@varel.studio`) are kept.
- Menu links follow D13 (`/shop/women/`, `/account/login/`); their translations got the same links
  and a recomputed `source_hash` (VAREL's `sourceHash`: SHA-256 of the JSON, 16 hex).
- Dates of activity (orders, events, returns, redemptions, codes, discounts' schedule, reviews,
  subscribers, emails, analytics) are `now() - interval …`, measured from when VAREL's seed ran,
  so the demo is always "the last 30 days". Catalogue and journal dates are absolute.
- The settings row is updated only while `updated_at = created_at` (never edited), so re-running
  the seed never overwrites an admin's settings.
- The template's job-board seed rows were dropped (D12).

To regenerate: see the header of `scripts/gen-seed.ts` (seed a VAREL-schema database with VAREL's
`prisma/seed.ts`, then `SRC_DATABASE_URL=… npx tsx scripts/gen-seed.ts`). It uses `pg`, which is
already installed (dependency of `@prisma/adapter-pg`, with `@types/pg`).

## Differences from VAREL

- Money is integer cents everywhere; `Discount.value` is two columns (above).
- Guest identity is `visitors` (D5); no `Session`/password/staff-invite tables.
- `staff` is a role with codenames, not `User.role` + `User.permissions[]`; VAREL's per-staff
  area list becomes custom roles in `/dashboard/roles`.
- Added CHECK constraints, `updatedAt` on most tables, a few keyset indexes
  (`(…, created_at DESC, id DESC)`) and the trigram indexes; VAREL's own indexes are all kept.
- The cart's guest/user exclusivity is not a CHECK (VAREL's merge-on-sign-in may briefly set both):
  enforce it in `lib/cart.ts`.

   `amountCents`, `db.shopOrder…`, `visitorId`, Int ids parsed from URL params with a validator).
   `lib/abandoned.ts` recovery token: `cid` is now a number (cart id).

   upsert the `visitors` row before writing a cart or wishlist row (FK).
4. **WP-15**: create the `CustomerProfile` row on sign-up (first/last name, locale, marketing opt-in).
5. **WP-20**: VAREL's customer list (`User` where role = customer) becomes `users` holding only
   `member` + `customer_profiles` (left join; a profile may be missing).
6. **Integrator**: migrations `20261101090000_varel_schema` then `20261101090100_varel_roles`
   (after the template's `20261029090000_payments`). The first needs `pg_trgm`

   A later `migrate dev --create-only` may propose `DROP INDEX "carts_abandoned_idx"` (partial
