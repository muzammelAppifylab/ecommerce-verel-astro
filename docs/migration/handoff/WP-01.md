## Differences from VAREL

- Hero translation overlay is stricter: translated CTA **urls** never win (VAREL's spread let them); only words come from the translation; image always the source's.
- Hero CTA urls and image src must be safe (`safeHref`: `/…` not `//…`, `http(s)://`, `mailto:`; image `/…` or `https://`), else the designed default.
- Menu items with unsafe URLs (`javascript:`, `data:`, `//…`) are dropped; ≤ 20 items, ≤ 20 menus.
- Caching: both routes answer `public, max-age=60` + `Vary: X-Locale` when the language came from an enabled `X-Locale`
  header, else `private, max-age=60` + `Vary: Accept-Language, Cookie` (VAREL: no-store). The home page itself uses
  `pageContext` (header shows signed-in state), so it stays `private, no-store`.
- No query validator on the two routes: the only input is `lang`, which `localeOf` accepts only when it is an enabled locale
  (anything else ignored, never 422, VAREL behaviour).
- Skeletons on the server-rendered sections are dropped (data or no section); New in shows its skeleton only when the server read failed.
- Title: Base appends the site name, so the designed default title is the site name alone; an admin `seoTitle` shows as `"<seoTitle> · <site>"` (Request 2).
- `piece.note` ("Free shipping over $150 …") stays static copy as in VAREL (not computed from `freeShippingThreshold`).
- Add-to-bag analytics (`add_to_cart`) not sent from the home: no browser `track` helper exists yet (Request 4).
