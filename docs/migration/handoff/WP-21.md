# WP-21 · Discounts admin: hand-off

`src/pages/admin/discounts/*` into `/site-api/manage/discounts` and `/dashboard/discounts`.

## What was ported

### Server (`src/server/routes/admin/`)
- `discounts.ts`: F3's `discountsAdmin` stub filled in place (one chained Hono, static paths before `/:id`):
  `GET /` (list, `method`/`status`/`q`, q also matches unique codes), `GET /preview`, `GET /names`,

## Differences from VAREL
- The list is capped at the newest 100 (order `createdAt desc, id desc`); the screen shows a notice at 100.
- Codes list: keyset `LoadMore` instead of numbered pages; CSV is streamed and capped at 20,000 rows; each CSV
  export writes an audit event `discount.codes.export` (new).
- Note limit is 200 on both sides (VAREL client said 120); the client gained the server maxima VAREL's client lacked.
- Code checks are exact upper-case matches (indexes) instead of `mode: insensitive`; codes are stored upper case.
- Bad or missing `:id` → 404 (not 422). Error codes are lower case (`code_taken`, `codes_exhausted`).
- VAREL's read-only staff mode is gone (reads need the same ability); `canWrite` checks stay.
- In-form on/off settings (combinable, active) are kit `Checkbox`es (kit rule: a choice saved with a form);
  the list row toggle is a `Switch` (applies at once).
- The "generating" progress bar (inline `<style>` keyframes) is a pending button + status text (CSP).
- Icons missing from the kit use fallbacks: duplicate → `copy`, activate → `check-circle`, deactivate → `ban`,
  generate code → `refresh`, buy X get Y → `shopping-bag`.
- Category/department pickers read `/manage/taxonomy/departments` (WP-18) and fall back to `/discounts/preview`
  lists when that route is not there (no product counts then).
