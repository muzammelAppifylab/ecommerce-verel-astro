## What was ported

- **Site API registry** (`src/server/app.ts`, VAREL `worker/index.ts`): one chained Hono app at
  `/site-api`. Order: `previewCookies` → `/webhooks` (Stripe, BEFORE `sameOrigin`/`csrf`, signature
  checked by WP-11) → `sameOrigin` → `csrf` → 64 KB body limit → `syncPermissions(CATALOGUE)` →
  default `Cache-Control: no-store` → `/health`, `/me`, template `/auth`, `/admin`, `/site` → the 22
  public modules → `/manage` (the store admin). `onError` maps thrown errors with `toProblem` and
  localizes the message/fields for `X-Locale` ≠ en (through `contracts.localizeMessage/localizeFields`).
- **Public route modules** (`src/server/routes/*.ts`): settings, menus, catalog (`/taxonomy`, `/products`),
  product, reviews, collections, search, posts (+ `/feed`), pages, contact, cart, wishlist, shipping
  (+ `/countries`), checkout, orders, returns, account, i18n (+ `/account/locale`, `/account/onboarding`),
  downloads, events, newsletter, media, payments-webhooks. Every VAREL public path is a slot with its
  method and path; each file's header lists path → contract type → owning package. Stubs answer
  `501 {error:'not_implemented', message}`; `/sitemap` slots (taxonomy, products, collections, posts,
  pages) and `/posts/feed` answer `{items: []}`. `/media/:key` answers VAREL's 404 for old links.
- **Admin modules** (`src/server/routes/admin/*.ts`, mounted at `/site-api/manage/<area>`): dashboard,
  analytics, products, inventory, taxonomy, collections, orders, returns, customers, subscribers,
  abandoned, discounts, posts, pages, menus, reviews, settings, tax-rates, shipping, payments, emails,
  translations, staff, activity, uploads. `admin/index.ts` applies `withViewer → requireAuth →
  requireManageArea → activityLog` once; moved paths are listed in its header (departments/categories
  under `/taxonomy`, CSV exports as `<area>/export.csv`, uploads via platform files, staff invites dropped).
- **Permissions** (`src/server/permissions.ts`, VAREL `middleware/permissions.ts`): the seven §7 entries
  with exactly F1's codenames (`site:shop_order:manage`, `site:customer:manage`, `site:product:manage`,
  `site:content:manage`, `site:discount:manage`, `site:analytics:read`, `site:store_settings:manage`),
  roles `['admin','staff']`, settings `['admin']`, group `Store`, abilities `manageOrders`,
  `manageCustomers`, `manageProducts`, `manageContent`, `manageDiscounts`, `viewAnalytics`,
  `manageStoreSettings`. Plus VAREL's area table: `PERMISSION_AREAS`, `AREA_CODENAMES` (staff =
  template `site:user:read`), `AREA_ABILITIES`, `areasOf`, `areasFromAbilities`, `MANAGE_AREAS`
  (segment → read/write need; settings/tax/shipping reads open to any staff, product/collection reads
  open to discounts), `areaFor`, `mayUseManage` (unmapped segment needs every area).
- **Contracts** (`src/lib/types/**`, VAREL `worker/types.ts`, `admin-types.ts`, `src/lib/api/types.ts`,
  `src/lib/admin/types.ts`): split per area (common, catalog, collections, content, cart, orders,
  account, reviews, settings, events; admin/{common, catalog, merchandising, sales, customers,
  promotions, content, analytics, store, emails, translations, staff, reviews}).
- **Validation** (`src/server/lib/validate.ts`, VAREL `middleware/validate.ts`): `json()`, `query()`,
  `params()` zod validators as first middleware (typed for `hc`), 422 `invalid_input` with dotted
  `fields` (localized for `X-Locale`), `parse()` / `InputError`, `zodFields`, field schemas
  (`emailField`, `requiredText`, `optionalText`, `multiValue`, `pageQuery`), and **`intId()` /
  `bigIntId()`** for F1's Int / BigInt ids in URL params.
- **HTTP helpers** (`src/server/lib/http.ts`): `wireCode`, `problemOf`, `apiError`, `notImplemented`,
  `toProblem` (domain `HttpError` by shape, zod, `HTTPException`, Prisma P2025/P2002), keyset

  `csvText`, `csvResponse`).
- **Cross-package stubs** (`src/server/lib/contracts.ts`): `sendTemplate` (WP-22), `refundOrder` /
  `restockOrder` (WP-11), `recordActivity` + `activityLog` middleware (WP-26), `localize` (F4/WP-25),
  `localizeMessage` / `localizeFields` (F4), **`queueEntityTranslation(db, entity, id, {requestUrl})`**

## Aligned with F1 (after merging wp/F1)

- Codenames identical to F1's `20261101090100_varel_roles` migration (tested).
- **Wire contract unchanged on purpose:** ids are STRINGS on the wire and money is a NUMBER in major
  units, as VAREL's API (documented in `src/lib/types/common.ts`). F1's Int ids and `…Cents` columns are
  database-side; serializers convert (F4 `fromCents`/`toCents`, `String(row.id)`), routes parse ids
  with `intId()`. Every Wave 1 prep spec (WP-03, WP-04, WP-11, WP-12, WP-18, WP-19) is written
  against this wire contract, so the types were NOT switched to Int/cents.
- Contract signatures that touch the database use F1 names in their docs (`db.shopOrder`,
  `amountCents`); `refundOrder`/`restockOrder` keep `id: number | string` as the specs quote them.

## Differences from VAREL

- `/api/*` → `/site-api/*`, `/api/admin/*` → `/site-api/manage/*` (paths that moved: `admin/index.ts`).
- Errors `{error: 'snake_code', message, fields?}` instead of `{error: {code, message, fields}}`;
  codes lower-cased, `VALIDATION_ERROR` → `invalid_input`.
- Admin lists are keyset (`CursorPage {items, nextCursor}`), no totals / page numbers.
- Staff permissions are role codenames, not `User.permissions[]`; the area check is central
  (`requireManageArea`), re-read per request.
- Auth routes, sessions, staff invites are the template's (VAREL `/auth/*`, `/staff-invites/*`,
  `/account/password` are not slots: the template's `/site-api/auth/*` serves them).
- `/sitemap.xml`, `/robots.txt` are Astro routes, not Worker HTML injection.
