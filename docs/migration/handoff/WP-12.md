# WP-12 · Checkout UI & confirmation: hand-off

Branch `wp/WP-12` (based on `wave0`). Storefront only: two SSR pages, one checkout island, two small
confirmation islands, and the shared checkout display components other packages import. No route, job,
model or portal screen.

Pages:
- `/checkout/`: parallel in-process reads (cart, settings/public, checkout/config, countries, account/overview
  when signed in), then shipping methods for the first country (primary saved address → Denmark → first).
  Bag unreadable → 503 + "We could not load your bag" + Try again; empty bag → 302 `/cart/`; guest checkout
  off + guest → "Sign in to check out" (no JS). `allowEmbeddedCheckout(Astro.csp, 'stripe')` only when the
  provider is Stripe. `CheckoutShell`, `noindex`.
- `/order/<n>/confirmation/`: raw `GET /orders/:number?email=`; 404/401/403 → 404 "We cannot find that order"
  (+ Sign in for guests), other failures → 503 + Try again; Pending → `ConfirmingPayment`, Failed →
  `PaymentFailed`, Paid/Refunded → `ConfirmationBody` (SSR). `Storefront`, `noindex`, `secretInUrl`
  (`<meta name="referrer" content="no-referrer">`). A page script drops Stripe's `payment_intent*` /
  `redirect_status` params with `history.replaceState(history.state, …)`.

## Differences from VAREL

- Guards run on the server (no bag spinner, no client redirect); the island gets everything as props.
- Pay button shows "Processing…" while working (new key `checkout.paying` in all 6 locales, per AGENTS.md
  pending labels).
- Confirmation download link is the guarded `/site-api/downloads/<file>?order=&email=` (VAREL used the bare
  filename); tracking links are https-only with `rel="noopener noreferrer"`.
- `track('checkout_start')` is not sent: there is no browser analytics helper in Wave 0 (see Requests).
- `sign_in_required` from the checkout shows the message (VAREL re-read settings).
