# F5 · Dashboard rebrand, kit extensions, screen registry: hand-off

Branch `wp/F5` (from `main`, with `wp/F1` merged so ids and names match). Owns `src/portal/routes.tsx`,
`src/portal/PortalApp.tsx`, `src/portal/api.ts`, `src/portal/queries.ts`, `src/portal/queries/*`
(stubs), `src/portal/screens/<area>/index.tsx` (stubs), `src/portal/ui/**`, `src/styles/global.css`,
`src/styles/app.css`, `src/layouts/App.astro`; also the kit tab on `src/portal/screens/components.tsx`
and `tests/portal-kit.test.ts`.

## What was ported / built

### Rebrand (VAREL admin look)
- `global.css`: VAREL palette as tokens (ink scale `--ink-000…900`, hairlines, signal colours),
  light + dark (`prefers-color-scheme` and `data-theme`), square corners, `--font-display`
  (Cormorant Garamond 500) and `--font-sans` (Lato 400/700) as `@font-face` from `/fonts/*.woff2`.
- `app.css`: the template's classes kept; appended "VAREL look" (13px Lato, tabular figures,
  Cormorant titles, ink active nav, hairline cards), access gate, screen placeholder, settings
  layout, and the CSS of every kit addition below.
- `App.astro`: preloads `/fonts/lato-400.woff2`; bundles every `src/portal/screens/**/screen.css`
  (eager `import.meta.glob`) so each Wave 1 screen keeps its own CSS in its own folder.

### Screen registry (`routes.tsx`)
One literal `createRoute` per VAREL `src/routes/admin/*` route, each lazy-loading
`screens/<area>/index.tsx` (named export) with its `validateSearch` and loader from
`queries/<area>.ts`:

`/`, `/analytics`, `/orders`, `/orders/$number`, `/returns`, `/returns/$id`, `/abandoned`,
`/customers`, `/customers/$id`, `/subscribers`, `/products`, `/products/new`, `/products/$id`,
`/inventory`, `/catalog`, `/collections`, `/collections/category-order`, `/collections/$id`,
`/reviews`, `/discounts`, `/discounts/new`, `/discounts/$id`, `/staff`, `/users`, `/roles`,
`/activity`, `/journal`, `/journal/new`, `/journal/$slug`, `/pages`, `/pages/$id`, `/navigation`,
`/settings` (layout) with `/`, `/checkout`, `/payments`, `/tax`, `/shipping`, `/inventory`,
`/emails`, `/languages`, `/privacy`, `/seo`; redirects `/settings/email` → `/settings/emails?tab=delivery`,
`/emails` → `/settings/emails`, `/shipping` → `/settings/shipping`, `/translations` → `/settings/languages`
(VAREL's old addresses, search carried over); `/account` (template); `/components` (dev only).

- `NAV_GROUPS` in VAREL's groups (Overview · Sales · Catalog · Store · Content), each item gated by
  its §7 ability (`hasAbility`, `AreaAbility` in `api.ts`); Settings pinned at the foot (store
  settings or content ability); counters beside Orders/Returns from `navCountsQuery`.
- Shell: VAREL wordmark when the site has no logo, "View store", theme menu, user menu, `AccessGate`
  (VAREL `AccessGuard`: a direct link to an area the role lacks shows a notice, not errors),
  route fade keyed by path (search changes stay still).
- `PortalApp.tsx`: plain query strings (`?payment=Paid,Pending&page=2`, VAREL's format) via
  `queries/search-params.ts` `parseSearch`/`stringifySearch`.
- `api.ts`: `manage<T>(path, {method, query, body})` (siteFetch to `/site-api/manage/*`, answers like
  `read()`), `toQueryString`, `AreaAbility`, `hasAbility`.
- `queries.ts` keeps the template's queries (job queries removed, D12) and re-exports
  `queries/<area>.ts`. Each area file has VAREL's search validator (typed, malformed values dropped),
  its constants (statuses, sorts) and stub loaders marked `WP-xx implements`.

## Differences from VAREL
- Components swapped per PLAN §6 (Card/Stat/DataTable/Drawer/Modal…); look via tokens, not Tailwind.
- Admin lives at `/dashboard/*` (D13); old VAREL `/admin/emails|shipping|translations` paths are
  in-app redirects under Settings, as VAREL had them.
- Users / Roles screens are the template's (Staff is a separate stub for WP-26).
- `BulkAction` takes an `IconName` and a `pending` state instead of a `ReactNode` icon.

## Requests
1. **F3** (`src/server/permissions.ts`): catalogue entries must expose the abilities named in
   `AreaAbility` (`manageOrders`, `manageCustomers`, `manageProducts`, `manageContent`,
   `manageDiscounts`, `viewAnalytics`, `manageStoreSettings`). Until merged, `/me` lacks them and
   the store nav items stay hidden (AccessGate shows "no access").
2. **F2** (`public/fonts/`): `lato-400.woff2`, `lato-700.woff2`, `cormorant-garamond-500.woff2`
   at those exact names; the dashboard references them (404 until F2 merges; system fallback meanwhile).
3. **F3** (D12): `src/portal/screens/jobs.tsx` and the jobs routes/queries were removed here; the
   server job routes and `JobsPage` type are F3's to remove.
4. **WP-16**: fill `fetchNavCounts` in `queries/overview.ts` (sidebar counters) from
   `GET /site-api/manage/dashboard`.
5. **WP-17**: `POST /site-api/manage/uploads` → `{fileId, upload}` and
   `POST /site-api/manage/uploads/:fileId/complete` → `{url}` (contract used by `ImageUploader`).
6. **Every Wave 1 screen package**: keep the export names that `routes.tsx` lazy-loads (listed in each
   `screens/<area>/index.tsx`) and the loader/validator names in `queries/<area>.ts`; screen CSS goes in
   `screens/<area>/screen.css`. `SeoPanel` and `BulkBar` are now in the kit: import them from `../../ui`.
7. **Integrator / every agent (local dev)**: use `127.0.0.1`, not `localhost`, in `DATABASE_URL`
   (`postgresql://varel:varel@127.0.0.1:5436/<db>`). With `localhost` the dev server (workerd) fails
   every sign-in with `Transaction API error: Unable to start a transaction in the given time`
   (the one-connection pool's connect exceeds Prisma's 2 s `maxWait`). Nothing to change in code.
