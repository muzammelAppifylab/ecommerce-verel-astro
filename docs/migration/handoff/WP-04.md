### Public API
- `GET /site-api/products/:slug/reviews?sort=newest|highest|lowest&pageSize=1..20&cursor=&page=` →
  `ReviewsResponse` (summary from one `groupBy`, `total = summary.count`, `nextCursor`), `public, max-age=60`
  (no viewer read); unknown / draft product or a malformed slug → 404 (`no-store`).
- `GET …/reviews/eligibility` (private) → `ReviewEligibility` + `postingAs` ("Mira H."). An expired access
  token answers 401 `token_expired` so `siteFetch` refreshes and retries.
- `POST …/reviews` (signed in) → 201 `ReviewSubmitResponse`. 403 `forbidden` (closed), 403 `verified_only`,
  409 `already_reviewed`, 429 `rate_limited`, 422 `fields`. Approved → `recomputeRating`.
- Exported helpers (admin + tests use them): `displayName`, `serializeReview`, `summarize`, `summaryOf`,
  `recomputeRating`, `reviewSettings`, `publishedProduct`, `eligibilityOf`, `reviewerName`, `cursorOf`,
  `afterCursor`, `SORT_ORDER`, `PUBLIC_SELECT`, `listQuery`, `submitBody`, `REVIEW_RATE_LIMIT`.

### Admin API (`/site-api/manage/reviews`, central guards, `site:product:manage`)
- `GET /` `?status=pending|approved|rejected|all&rating&verified&productId&q&cursor&pageSize` →
  `AdminReviewList {items, nextCursor, counts}`. Pending is a queue (oldest first); the others newest first.
  Counts: one grouped query, honouring rating/verified/product/q but not the status.
- `POST /bulk {ids (1–100), action}` → `{updated}`; `PATCH /:id {status?, reply?}` → `AdminReview`
  (`reply: ''` → null; `{}` → 422 `fields.status`); `DELETE /:id` → 204. Every status change / delete
  recomputes the product's `ratingAvg` / `ratingCount` (reply-only does not).

### Storefront island (for WP-03)
```astro
---
import ReviewsSection from '@/components/reviews/ReviewsSection.astro';
import {loadReviews} from '@/components/reviews/load';
const [product, reviews] = await Promise.all([/* product read */, loadReviews(api, slug)]);
---
<ReviewsSection slug={product.id} name={product.name} initial={reviews} />
```
`initial` may be left out (the section reads it). `loadReviews` never throws (`null` → island retries in
the browser). Reviews off with none written renders nothing. `client:visible`; first page is in the SSR
HTML; eligibility loads in the browser (no visitor data in the page). When the visitor's own review goes
live the island dispatches `window` event `varel:reviews-changed` (`{detail: {slug}}`).

### Dashboard `/dashboard/reviews`
Status tabs with counts (status in the URL, pending default), search (submits on Enter), rating filter,
"Select page" (tri-state), review cards (approve / reject / reply inline / delete with `useConfirm`;
only the acted card's button is pending), kit `BulkBar` (approve / reject / delete with confirm), "Load
more" (keyset `useInfiniteQuery`), loading / empty (filtered and per-status copy) / error + retry, and
the two review settings (switches; disabled without `manageStoreSettings`, while saving, and the second
while reviews are off; "Unavailable" when the settings read failed). Toasts as VAREL.

## Differences from VAREL
- Keyset paging: the PDP pager keeps a cursor stack (Previous / Next, "page n of m" from `total`); the
  admin list uses "Load more" instead of page numbers. `validateReviewsSearch` no longer keeps `page`.
- Orders and reviews are matched by email only when the viewer's email is verified (VAREL matched any
  account email: anyone could register with a buyer's address and review as them).
- 10 reviews per account per hour (429 `rate_limited`): security.md rate limit on writes.
- An erased account's name (`Deleted customer`) is shown as is (VAREL: "Deleted C.").
- Bulk answers `{updated}` (VAREL `{count}`).
- Portal look: kit `Tabs`, `Card`, `Switch`, `StatusBadge` (pending `warning`, approved `success`,
  rejected `danger`), `Badge` for "Verified purchase", small inline SVG stars (the portal does not
  import storefront components).
