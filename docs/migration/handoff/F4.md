## Requests answered in this run (spec writers / F1)

- **F1 visitor ids**: cookie ids of 32–64 hex chars are accepted (`VISITOR_RE`, `VISITOR_ID_MAX = 64`; new ids
  stay 48). `ownerOf` upserts the `visitors` row for guests, and `getOrCreateCart` does too before creating a
  guest bag (FK). Wishlist writes must go through `ownerOf` (or call `ensureVisitor`) first.
- **Bounded loaders**: `CATALOG_LIMIT` is **100** (was 500). `allProducts(db, where?)` takes a database filter;
  `listProducts` filters department / category (slug or English name) and `featured` in the database before
  the in-memory facets (index `products(status, position, id)` and the dept/category indexes). `relatedProducts`
  reads the product, then same-dept/category rows, then (only if short) the rest — two bounded reads instead of
  the whole catalog. `collectionBySlug` reads only the linked products (≤ 100 links).
- **Explicit select `ProductRow`**: `productSelect` (serializers.ts) lists exactly what `serializeProduct`,
  filters and facets read (no cost, weights, packages; images ≤ 20, variants ≤ 100). `ProductRow` is its
  payload. `productInclude` stays (same narrow relations) for callers that need extra product columns; its rows
  are assignable to `ProductRow`.
- **`cartInclude`**: lines now use `cartLineSelect` (explicit select, no product description) with
  `take: BAG_LINE_LIMIT` (100). `addLine` refuses a 101st distinct line with `409 BAG_FULL` "Your bag is full.
  Remove a piece to add another" (bounded check, no `count()`).
- **`verifyRecoveryToken(secret, token): Promise<number | null>`** is in `src/server/lib/abandoned.ts` next to
  `recoveryToken` / `recoveryUrl`; the cart id (`cid`) is a number. `ABANDONED_SCAN_LIMIT` is 100.

## Differences from VAREL

- Money is integer cents in the database; libraries return currency units as VAREL's contract did.
- Ids: departments, categories, carts, lines, discounts… are `Int`; serializers send them as strings as VAREL did.
- Guest identity is `visitor_id` + `Visitor` (no Session); `mergeGuestIntoUser(db, visitorId, userId)` is not
  wired to sign-in (template auth has no hook): callers merge lazily (WP-09 B4).
- Catalog order ties break on `id` (the product slug) instead of `name` (index order); the seed has distinct
  positions so nothing changes there.
- A bag holds at most 100 distinct lines; listings, related and collections read at most 100 products.
- i18next is replaced by a small `t()` (`{var}` interpolation; plurals via `Intl.PluralRules`, `key_<form>` then `key_other`, as VAREL's
  JSON uses). Islands get their dictionaries as props (`dictionary(locale, ns)` → `useT(dict, ns)`).
- `tests/money.test.ts`: the JPY `formatMoney` case compares with `Intl` instead of a literal `￥` (the symbol
  depends on the ICU build).

## Requests

1. **Integrator / F3** (`src/server/backend.ts` or the in-process client): forward `x-locale` with the other
   forwarded headers, so in-process Site API calls answer in the URL's language without each page passing it.
2. **WP-01 / every localised public page**: must be SSR (`prerender = false`); a rewrite cannot reach a
   prerendered page (the middleware then 302s to the English URL).
3. **F3**: `tests/permissions.test.ts` (2) and `tests/integration/admin.test.ts` (1) still reference the
   removed job board (`JOB_MANAGE`, `manageJobs`, `/site-api/jobs/manage`), and `src/portal/{queries.ts,
   routes.tsx,screens/jobs.tsx,screens/overview.tsx}` fail `tsc` for the same reason — F3/F5 WIP, not F4.
4. **WP-02**: `listProducts` already narrows by dept/category in the database, so the second "base counts"
   read is cheap; a `withCounts` option was not added (signature unchanged).
5. **WP-09**: `BAG_FULL` server message exists (`addLine`); map it in the bag UI. `cartInclude` lines carry
   only the `cartLineSelect` fields — read anything else with your own select.

## Known gaps

- `npx astro check` is not installed; `npx -p typescript@5.9.3 tsc --noEmit -p .` is clean for every F4 file
  (the only errors are the F3/F5 job-board leftovers above).
- Listing facets and search stay in memory over ≤ 100 rows (VAREL parity). A catalogue above 100 published
  products per department/category needs database-side facets and keyset paging.
- Guest bags in the editor Preview: the Preview mirrors only auth cookies, so `visitor_id` may not persist
  there; test guest flows on `npm run dev`.
- `npm test` with `TEST_DATABASE_URL`: 420 / 424 pass; the 3 failures listed in Request 3 belong to F3.
