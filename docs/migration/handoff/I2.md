# I2 · Security & tests (Wave 2)

Branch `wave2/I2`. Scope: `docs/agent/security.md` over every Site API route, guard and ownership tests,
rate limits on the store's public writes, Stripe webhook gate tests, CSP on rendered pages, Worker limits,
the flaky vitest worker crash.

## What was added

- **Rate limits** — `src/server/lib/rate-limit.ts` + table `rate_hits`
  (`prisma/migrations/20261102090000_i2_rate_hits`, model `RateHit`). The template's limiter has fixed
  sign-in kinds, so the store counts its own hits: record first, then a bounded read
  (`take: limit + 1`, index `(kind, subject, created_at)`); over the limit it throws
  `HttpError(429, 'RATE_LIMITED')` with `Retry-After`. The subject is an HMAC (`subjectHash`, keyed by
  `JWT_SECRET`) of the client IP (`cf-connecting-ip`) or the account id: no raw IP or email is stored.
  Pruning is bounded and needs no schedule (the subject's own expired rows on each hit; ~2 % of hits
  delete up to 500 rows older than a day).

  | Kind | Limit | Where |
  | --- | --- | --- |
  | `review` | 10 / h per account (attempts) | `POST /products/:slug/reviews` (WP-04's 5 posted / h stays) |
  | `newsletter` | 10 / h per IP | `POST /newsletter` (WP-20's global flood guard stays) |
  | `contact` | 5 / h per IP | `POST /contact` (WP-07's per-email throttle stays) |
  | `events` | 120 / min per IP | `POST /events` (when WP-16 is merged; see below) |
  | `returnsLookup` | 10 / 15 min per IP | `POST /returns/lookup` |
  | `returnsCreate` | 10 / h per IP | `POST /returns` |
  | `orderLookup` | 30 / 15 min per IP | `GET /orders/:number?email=`, `POST /orders/:number/cancel` with an email |
  | `checkout` | 20 / 10 min per IP | `POST /checkout` |
  | `checkoutSync` | 60 / 10 min per IP | `POST /checkout/:number/sync`, `/cancel` |
  | `download` | 60 / h per IP | `GET /downloads/:file` by order + email (guest links) |
  | `export` | 3 / h per account | `GET /account/export` |
  | `cartEmail` | 10 / h per IP | `POST /cart/email` |
  | `search` | 60 / min per IP | `GET /search` (WP-08 request) |

- **Tests** (integration, `TEST_DATABASE_URL`):
  - `tests/integration/route-guards.test.ts` — sweeps Hono's own route registry (`app.routes`), so routes
    added later are covered: every `/site-api/manage/*` route answers 401 signed out and 403 to a
    customer; every storefront write either has `requireAuth` in its chain or is on the reviewed
    `PUBLIC_WRITES` list; no route (guest or owner) answers 500 to junk input (bad cursors, negative page
    sizes, 300-char queries, prototype keys, NaN amounts).
  - `tests/integration/ownership.test.ts` — BOLA: another customer gets 404 (never 403, never the data)
    for addresses (read/patch/delete), orders (by number, with a wrong email, cancel), downloads; a
    number-only returns look-up never shows the email or address.
  - `tests/integration/rate-limits.test.ts` — each limit trips at its number with `Retry-After`, other IPs
    are unaffected, subjects are HMACs, pruning is bounded; the Stripe webhook accepts a signed event
    cross-site without CSRF and refuses missing / wrong-secret / stale / tampered signatures, signed non-JSON,
    bodies over 512 KB, and answers 503 without `STRIPE_WEBHOOK_SECRET`.

## Fixes found by the sweep / review

- `src/server/lib/shipping.ts`: no shipping zone at all threw a plain `Error` (500 on `/cart/totals`,
  `/shipping/methods`); now `503 shipping_not_configured`.
- Logs: `console.error(…, err)` printed whole error objects (can carry request data) in
  `lib/activity.ts`, `lib/cart.ts`, `lib/contracts.ts`, `lib/i18n/localize.ts`, `lib/i18n/translate.ts`,
  `lib/locale.ts`; now the message only.
- `src/server/lib/cart.ts`: guest wishlist merge did one upsert per item; now one `createMany`
  (`skipDuplicates`).
- `src/components/checkout/StripePayment.tsx`: Stripe Elements loaded Lato from Google Fonts inside
  Stripe's frame (the visitor's IP to Google; WP-12 request); removed, the font stack falls back.

## Reviewed, no change

- Raw SQL: only tagged templates; `Prisma.raw` only on constants (`products-shared.ts`). No
  `$queryRawUnsafe`.
- HTML: `set:html` only for JSON-LD through `jsonLdText` (escapes `<`, `>`, `&`); no `innerHTML` with
  data; every `target="_blank"` has `rel="noopener noreferrer"`; no `style=""`, inline handlers or
  `is:inline` in `.astro`, no `style={}` in islands.
- Mass assignment: zod objects strip unknown keys; `tax-rates` passes the parsed object (three known
  fields) — acceptable.
- Unbounded reads: every `findMany` without `take` is bounded by an `id IN (validated list)` or one
  order's lines; loops with queries are per order line inside one transaction (conditional stock
  updates) or the orders CSV (40 keyset pages max).
