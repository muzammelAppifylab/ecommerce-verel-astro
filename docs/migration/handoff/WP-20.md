Endpoints (all `/site-api/manage/*` behind the central area guard, area `customers`):

- `GET /customers` → `CursorPage<AdminCustomerRow>` (`q` ≤ 5 words over email, account name, profile first/last name, phone; `role` multi `customer|staff|admin`; `sort` `createdAt|email|name` ±; keyset, 25 default, ≤ 100). Stats (orders, Paid spend, last order; linked + guest-by-email orders) for the page in ONE raw query; newsletter = profile opt-in OR subscriber row.
- `GET /customers/:id` → `AdminCustomer` (10 recent orders, ≤ 20 addresses primary first, wishlist count capped at 100).
- `PATCH /customers/:id` → profile edit (`firstName`, `lastName`, `phone`), upserting `CustomerProfile`; never touches `users`.
- `GET /customers/:id/export` → `CustomerExport` attachment (`site:user:update` required; audited `customer_data_exported`).
- `DELETE /customers/:id` `{confirmEmail}` → 204 (`site:user:update`; typed email checked on the server; only derived role `customer`, never self → else 409 `not_a_customer`; `account_deleted` email sent first via `sendTemplate`; then in one transaction F4 `anonymiseCustomer` + `users` row delete; audited `customer_deleted`).
- `GET /subscribers` → `CursorPage<AdminSubscriber>` (`q` words over email OR source; sort `createdAt|email`).
- `GET /subscribers/export.csv` → streamed CSV `Email,Source,Subscribed`, pages of 100, **cap 10,000 rows**, formula-escaped, `private, no-store`, audited `subscribers_exported`.
- `DELETE /subscribers/:email` → 204, also clears `CustomerProfile.marketingOptIn`; 404 `not_subscribed`.
- Public `POST /site-api/newsletter` `{email, source?}` → 204 (idempotent, never overwrites `source`; sets the account's opt-in); 422 `fields.email`; global flood guard 429 `rate_limited` (> 30 sign-ups in the last minute).

Screens: customers list (search, Role filter popover, sort select, clear filters, row menu, select + `BulkBar` copy emails / export CSV, `LoadMore`, empty/error states), customer detail (header, 4 stats, recent orders, addresses, profile card + edit drawer, role card + dialog through the template users API, data and privacy card with export + typed-email delete modal; 404 state), subscribers (search, server CSV download via `siteFetch` blob, row menu, bulk copy/export/remove with `useConfirm`, settle with concurrency 5).

## Differences from VAREL
- Keyset pages, no totals ("25+ accounts" via `pageCount`); the orders/spent/last-order sorts are gone (need totals); subscriber `source` sort dropped.
- Roles are template roles. VAREL's `PATCH {role}` is gone: the Role dialog calls `PUT /site-api/admin/users/:id/roles` (template anti-escalation and last-owner rules apply; `member` and custom roles are kept). Derived role (display/filter only): owner/admin → admin; any other non-`member` role → staff; else customer.
- `PATCH /customers/:id` edits the shop profile (new; Profile card "Edit" drawer).
- Delete removes the `users` row (the template has no soft delete) after anonymising shop data; the typed confirmation is also checked on the server.
- Export/delete gated by `can(c, 'site:user:update')` instead of VAREL `requireAdmin`.
- Newsletter `source` restricted to `[a-z0-9_-]` ≤ 40 and lower-cased; global flood guard added.
- CSV export capped at 10,000 rows (stated in the screen hint); client CSV also formula-escapes.
- Activity rows (`customer.update`, `customer.delete`, `subscriber.delete`) are left to WP-26's `activityLog` middleware (no explicit `recordActivity`, to avoid a double row).
