## How sending works now (differences from VAREL)

- **Outbox** (default): row `stored` at once, nothing delivered (as VAREL).
- **A provider, from a route** (`requestUrl` given): row `queued`, then `sendJob(requestUrl, 'send-email',
  {messageId}, {key: 'email-<id>'})`. A refused job (`E_JOBS_RATE_LIMITED`, paused…) leaves the row queued; the
  sweep delivers it (Request R3). Job data never holds the address, the email or a key.
- **From a job** (no `requestUrl`), admin test sends and resends: delivered inline, awaited (≤ 10 s each).
- **Delivery** claims the row (`claimedAt`, stale after 5 min) so a repeated job never sends twice in parallel;
  a retryable failure (network, timeout, 408, 429, 5xx) keeps it `queued` and the job throws (platform retries);
  on the last try it fails. Missing key or endpoint → `failed` + `DontRetry`. A 4xx refusal → `failed`, job done.
- **Sweep** (`{sweep: true}`): fails rows queued ≥ 7 days ("Not sent within 7 days"), then delivers up to 10 rows
  queued > 2 min, five at a time.
- **Retired templates**: `password_reset` (platform) and `staff_invite` (template Users screen) are hidden in the
  admin (404 on `:key`), and `sendTemplate` with them logs and records nothing.
- **Reads need Store settings** (`MANAGE_AREAS.emails` has no `read`): VAREL let any staff read the log; the
  outbox holds customer addresses and order contents.
- **Template stats** come from counters kept on write (not a `groupBy` per request); the log is keyset-paged
  ("Load more", no page numbers, no totals); status counts are bounded (`100+`).
- **Order emails** all use `orderVars`: account holders get their account order link
  (`/account/orders/<n>/`), guests the confirmation link (`/order/<n>/confirmation/?email=`); zero tax prints
  empty; `paymentMethod` = "Visa ending 4242". VAREL's confirmation used the guest link for everyone and printed `$0`.
- **Origin** for links = `config.siteUrl`, else the request origin, else none (link buttons drop out).
- **Locale**: explicit → related order (id or number) / return's order / user's `CustomerProfile.locale` / cart →
  store default; only enabled locales; translation per field falls back to the source; staff templates always default.
- **Preview iframe** is CSP-safe: inline styles moved to `data-s` and applied through the CSSOM on load; `<style>`
  becomes a constructable stylesheet; `<base target="_blank">`; sandbox without scripts. Verified: no CSP errors.
- **Viewer** shows delivery tries; the Delivery tab saves through `PATCH /manage/emails/delivery` (not WP-23's
  settings draft) and shows only whether `EMAIL_API_KEY` is added.
- Icons not in the kit yet are replaced by the nearest ones (heading → baseline, button → link, row → list,
  divider → minus, insert variable → plus, phone width → phone) (Request R6).

## Owner setup (for I1's README)

- Provider key: owner secret **`EMAIL_API_KEY`** (Resend API key, Postmark server token, EzyStudio key; optional
  for webhook, sent as `Authorization: Bearer`). Test value in the Preview, live value in production.
- Verify the sending domain with the provider; set From name/address under Settings · Emails · Delivery.
- Jobs: at most 10 jobs are added per minute by default. Mail beyond that waits for the 5-minute sweep (once R3
  lands) or the owner raises the limit in the Jobs tab.
