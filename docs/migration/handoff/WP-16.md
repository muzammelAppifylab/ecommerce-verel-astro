Usage for other packages (browser islands):
```ts
import {track} from '@/components/layout/analytics';
track('product_view', {productId});        // WP-03 PDP mount
track('add_to_cart', {productId});         // WP-09 after a successful add
track('checkout_start');                   // WP-12 checkout mount
track('search', {query, results});         // WP-08 after its settle debounce
```
`track()` never throws, is a no-op on the server and without `hasConsent('analytics')`, dedupes the same
event within 1 s, batches ≤ 20 every 2 s.

## Differences from VAREL (deliberate)
- **Transport**: `siteFetch(..., {keepalive: true})` instead of `navigator.sendBeacon` — the Site API's CSRF
  check needs a header a beacon cannot carry (and siteFetch carries the Preview's cookies). The CSRF token is
  pre-fetched on the first consented event.
- **Session id** = the F4 `visitor_id` cookie (`visitorIdOf(c)`, set by `/events` when absent), not `varel_sid`.
- **Aggregation in Postgres**: VAREL loaded every order into the Worker; here every figure is a tagged
  `$queryRaw` aggregate over a date-bounded, indexed range returning a few small rows. Counters are
  **capped** (`LIMIT` in a subquery: open orders / pending returns 1 000, customers 10 000). This is the
  documented exception to "no count() per request" for two staff-only report screens.
- **Customers** = users with role `member` and none of `owner/admin/staff` (template roles, no `User.role`).
- **Sidebar counters** have their own cheap `GET /dashboard/counts` instead of reading the whole dashboard.
- **Privacy**: tracked paths drop `token`, `email`, `code` query params; dashboard/portal paths are never tracked.
- **Invalid calendar dates** (`2026-02-31`) → 422 (VAREL rolled them over).
- **`/events` DB failure** → logged, still 204 (VAREL 500; the beacon never reads the answer).
- **Recent orders**: no row click / `OrderRowMenu` (row menu is WP-19's; the order number is the link).
- **No entrance stagger / inline bar widths** (CSP): bars are kit `ProgressBar`.
- Store currency + "analytics is off" notice come from `GET /manage/settings` (WP-23) via
  `reportSettingsQuery` (key `['admin','settings','report']`); until WP-23 merges that read is 501 → USD,
  notice hidden.
