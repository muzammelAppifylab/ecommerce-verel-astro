### API

- `GET /site-api/taxonomy`: `Department[]` `{name, slug, label, count, categories:[{name, slug, label, count}]}`
  in `position` order (explicit selects, ≤ 100 departments, ≤ 100 categories each). `name` and `label` are the
  request-language name (VAREL put the translated name in `name`); slugs unchanged. Counts are tallied in JS from
  one bounded read of published products (`CATALOG_LIMIT`), sold-out included (VAREL parity; no `_count`).
  Every department and category is listed, empty ones too.
- `GET /site-api/taxonomy/sitemap`: `{items:[{path:'/shop/<d>/'|'/shop/<d>/<c>/', updatedAt}]}` (the slot
  F3's `sitemap.xml.ts` reads), every department/category, `public, max-age=3600`.
- `GET /site-api/products`: VAREL's query (`dept, category, q, color, size, material, brand, tag, maxPrice,
  sort, limit, featured`) via F3 `query()` + zod, 422 `invalid_input` with field messages; multi-values
  comma-separated or repeated (`multiValue`, extra values dropped) with a per-value length cap. **`limit`
  defaults to 100** (template cap; `total` still counts every match). New `base=dept|category`: also returns
  `base: {facets, priceMax, total, counts}`, the route-scope listing (no facet filters, no `q`) that VAREL's
  pages read with a second browser call; computed by a parallel second `listProducts` and `facetCount` ported
  to the server (`facetCounts`). The island never asks for `base` again except when retrying after a failed
  server read.
- Cache: `public, max-age=300` (taxonomy) / `60` (products) + `Vary: X-Locale` only when the request names its
  language in `X-Locale` (pages and islands always do); otherwise `private, no-store`.

### Pages

- `/shop/`, `/shop/<dept>/`, `/shop/<dept>/<cat>/` (and `/da/…` etc. via the locale middleware): SSR, reads in
  parallel (`pageContext` ∥ taxonomy ∥ products+base), first grid in the HTML (island needs no first fetch),
  `sort=name` applied server-side too. `Cache-Control: private, no-store` (pageContext).
- Status: unknown department, or a category not in THAT department (`/shop/men/dresses/`), or a different-case
  slug → **404** + noindex + "We cannot find that collection"; taxonomy read failed → **503** + retry link
  (never 404 on an outage); products read failed → 503 with the error state. The status is set in the page
  frontmatter (a child component's frontmatter runs after streaming starts, too late for status/headers).
- Category pages ignore `?category=` (route wins, VAREL spread order), hide the category facet/chips, no
  `newest` in the inline sort; category chips keep `?sort=` and drop filters; department nav resets all.
- Hero count `[data-catalog-count]` (outside the island) is updated by the island via `textContent`.
- States: ready, refetching (previous grid `opacity-60`), skeleton (retry only), error + Try again, no match +
  Clear filters, category empty (decided by `base.total`), 404, 503.

## Differences from VAREL

- One request instead of two: base facets/counts/price ceiling come with the list (`base=`), counts computed on
  the server; the browser never receives the base items.
- `limit` default 100 and no paging (VAREL returned every match). In-memory filtering over ≤ `CATALOG_LIMIT`
  (F4: 100) published products per dept/category scope — no keyset cursor (known deviation from the template's
  `{items, nextBefore}` list shape).
- Refetch failure while results are shown: previous results stay and an error toast appears (VAREL silently kept
  them).
- Filter changes use `history.pushState` (price slider: `replaceState`) keeping Astro's `history.state`; no
  `astro:page-load` fires for them (VAREL tracked route changes only, so analytics parity holds).
