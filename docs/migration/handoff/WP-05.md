## Differences from VAREL

- Collection and category ids are `Int` in the DB; strings on the wire (F3 contract), parsed in the route (`abc` → 404).
- A collection holds at most **100** products (VAREL 500): "Use 100 products or fewer". Category order reads/orders at most 100 products (noted in the UI).
- `PATCH /manage/collections/product-order` (VAREL `PATCH /api/admin/products/order`) takes `{category, productIds}` and answers the full `CategoryOrder` (VAREL answered `{categoryId, productIds}`; the screen only re-reads).
- Image `creditHref` must be https (VAREL accepted any string). Uploaded images: any site-relative path (`/__platform/files/…`) or https.
- Pages are SSR: no loading skeletons. The rich description is rendered on the server (no hydration): custom colours painted by VAREL's client RichText after hydration are not applied; palette classes are.
- Page title: `seoTitle || title`, and `Base` appends " · <site>" (VAREL: "{title} — {store}").
- List quick toggles disable only the acted-on row (VAREL disabled all rows).
- The list's Published/On-home switch columns show from 1024 px (sidebar + content); below that, status badges.
